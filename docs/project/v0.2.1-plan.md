# v0.2.1 Plan

This document lists patch-sized follow-up candidates after the v0.2.0 locale-aware baseline.

It is a planning note, not a release announcement.

## Patch Scope

v0.2.1 should focus on corrections and hardening that do not break existing `ko-KR` forks.

Good candidates:

- documentation corrections
- validation hardening
- minor fixture fixes
- issue template cleanup
- release note corrections
- compatibility clarification
- safe bug fixes

Avoid in v0.2.1:

- removing `ko-KR` legacy webhook fallback
- removing `ko-KR` legacy artifact mirrors
- changing default locale away from `ko-KR`
- claiming mature `en-US` support
- adding large provider rewrites

## Candidate Issues

- Confirm README, release docs, and localized setup docs describe v0.2.0 consistently.
- Add focused locale-config validation checks if gaps are found.
- Add small fixtures for any documented `en-US` validation claims.
- Improve issue template wording based on maintainer feedback.
- Tighten provider/source policy examples when a source suggestion reveals ambiguity.
- Correct stale v0.1 references that are not historical release notes.

## Acceptance Criteria

- `git diff --check` passes.
- `python3 scripts/check-doc-format.py` passes.
- `./scripts/validate.sh` passes or pre-existing failures are documented.
- No generated `reports/` files are committed by default.
- No secrets or webhook URLs appear in docs or fixtures.
- `ko-KR` behavior remains compatible.
- `en-US` remains honestly documented as foundation/experimental.
