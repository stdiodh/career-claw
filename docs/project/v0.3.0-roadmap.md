# v0.3.0 Roadmap

This document lists larger feature candidates that should not be squeezed into v0.2.x patch work.

It is not a delivery promise.

## Provider Maturity

Possible work:

- move provider-specific behavior out of `collect-kr-feeds.py` in small steps
- define provider metadata and output contracts
- add provider fixtures and smoke checks
- improve failure reporting when optional credentials are missing
- document provider-specific rate-limit and source-policy constraints

## en-US Maturity

Possible work:

- improve `en-US` source lists
- validate English provider output with more fixtures
- review English news quality and source reliability
- separate Korean-centered assumptions from shared collector behavior
- document what remains experimental

## Source Quality

Possible work:

- richer reliability scoring
- duplicate-source handling
- source freshness checks
- spam and advertorial detection rules
- source review reports for maintainer inspection

## OSS Candidate Filtering

Possible work:

- improved maintainer-signal scoring
- clearer linked-work diagnostics
- better fallback routines when no safe candidate exists
- additional repository profiles after review

## Locale Expansion

New locales should wait until:

- source review capacity exists
- maintainers can review the language or region
- locale-specific docs can be maintained
- validation fixtures can be added
- provider behavior is clear

Additional locale support should not break `ko-KR` or overstate maturity.

## Workflow Improvements

Possible work:

- richer artifact summaries
- clearer run summaries
- more targeted validation artifacts
- optional workflow controls that remain safe for forks

Persistent services, databases, dashboards, Discord Gateway Bots, Slash Commands, account systems, and recruiting-matching services remain out of scope unless the project direction changes explicitly.
