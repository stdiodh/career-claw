# Backend Career Question Guide

> Language: [한국어](./backend-career-question-guide.md) | [English](../../en/contributing/backend-career-question-guide.md)

## Purpose

백엔드 커리어 질문을 더 잘 작성하는 방법을 안내합니다.

질문자를 평가하기 위한 프로젝트가 아닙니다.

질문은 더 나은 학습 주제, 커리어 브리핑, 실무 지식 카드, 출처 검토 기준을 만들기 위한 자료입니다.

막막함을 구체적으로 적을수록 maintainer가 도움이 되는 방향으로 정리하기 쉽습니다.

## What to include

좋은 질문에는 다음 정보가 포함됩니다.

- 현재 학습 단계
- 관심 기술 스택
- 목표
- 시도해 본 것
- 막힌 지점
- 원하는 도움의 형태
- 참고한 자료가 있다면 공개 URL

모든 항목을 완벽히 적을 필요는 없습니다.

하지만 "무엇이 막막한지"와 "어떤 도움을 원하는지"는 꼭 적어 주세요.

## Good question examples

좋은 질문 예시:

> Java 문법과 SQL 기본은 공부했고 Spring Boot 프로젝트를 시작하려는데, 게시판 이후 어떤 주제가 백엔드 포트폴리오에 적합한지 모르겠습니다.

좋은 질문 예시:

> Redis를 공부하고 있는데 cache aside, write through, TTL을 언제 구분해야 하는지 Daily Brief에서 다뤄 주면 좋겠습니다.

좋은 질문 예시:

> 백엔드 인턴 공고를 볼 때 우대사항과 필수사항을 어떻게 구분해야 하는지 알고 싶습니다.

좋은 질문 예시:

> MySQL index와 query plan을 공부했지만 실제 프로젝트에서 어떤 지표를 봐야 하는지 모르겠습니다.

좋은 질문 예시:

> AWS 배포를 처음 해 보려는데 EC2, RDS, S3 중 어떤 순서로 실습하면 좋을지 알고 싶습니다.

## Weak question examples

약한 질문 예시:

> 뭐부터 해야 하나요?

약한 질문 예시:

> 백엔드 취업 가능할까요?

약한 질문 예시:

> 제 이력서를 다 평가해 주세요.

약한 질문 예시:

> 합격 보장 로드맵 만들어 주세요.

약한 질문 예시:

> 아무 자료나 추천해 주세요.

이런 질문은 현재 상황과 원하는 도움의 형태가 부족해 답하기 어렵습니다.

가능하면 현재 단계와 막힌 지점을 한두 문장이라도 추가해 주세요.

## Personal information safety

공개 issue에는 다음 정보를 올리지 마세요.

- 전화번호
- 주소
- 주민등록번호
- 사적인 계정
- 비공개 회사 정보
- API key
- webhook URL
- token
- 개인 이메일
- 비공개 문서 링크

이력서 전체, 포트폴리오 비공개 링크, 회사 내부 자료도 공개하지 않는 것이 안전합니다.

민감한 맥락은 익명화하거나 범위를 줄여서 설명해 주세요.

## How questions improve Career Feed

좋은 질문은 다음 개선으로 이어질 수 있습니다.

- Daily Backend Brief의 학습 주제 후보
- Backend Career Site Radar의 해석 기준
- OSS 후보 설명에서 beginner가 어려워하는 지점
- 문서와 issue template의 명확성

질문은 개인의 합격 가능성을 판단하기 위한 자료가 아닙니다.

학습자의 반복적인 막막함을 구조화하기 위한 자료입니다.

## Maintainer review

질문이 프로젝트 범위와 맞는지 확인합니다.

질문이 너무 개인 평가 중심이면 범위를 좁혀 달라고 요청할 수 있습니다.

질문에 민감 정보가 포함되어 있으면 삭제나 수정 요청을 할 수 있습니다.

질문이 좋은 브리핑 주제로 이어질 수 있으면 관련 문서나 roadmap에 반영할 수 있습니다.

모든 질문이 바로 브리핑에 반영되는 것은 아닙니다.

반영 여부는 반복성, 학습 가치, 안전성, maintainer review 가능성에 따라 달라집니다.
