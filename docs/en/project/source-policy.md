# Source Policy

> Language: [한국어](../../kr/project/source-policy.md) | [English](./source-policy.md)

This policy helps contributors suggest useful public sources and avoid low-quality or unsafe inputs.

For the shared baseline, see [Source Policy](../../project/source-policy.md).

## Good Sources

Good sources are public, stable, relevant, and reviewable.

Examples:

- official documentation
- official engineering blogs
- public GitHub repositories and issues
- public career pages
- reliable technology media
- public RSS or Atom feeds

## Sources To Avoid

Avoid sources that:

- require private login context
- expose private Discord, repository, or personal details
- mainly exist for SEO, affiliate, referral, or advertorial traffic
- duplicate content without an original source
- push investment advice or price movement without risk context
- cannot be validated by maintainers

## Locale Notes

`ko-KR` is the default supported locale and may use Korean source assumptions.

`en-US` is a v0.2 foundation / experimental preset. Source suggestions are welcome, but do not describe the preset as mature until evidence exists.

## Issue Checklist

When suggesting a source, include:

- source URL
- locale
- source type
- update cadence
- reliability tier
- why it helps the target audience
- known risks

Do not include secrets, webhook URLs, API keys, private links, or personal identifiers.
