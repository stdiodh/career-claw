# v0.2.0 Release Notes

> Language: [한국어](../../kr/release-notes/v0.2.0.md) | [English](./v0.2.0.md)

Career Feed v0.2.0 adds the locale-aware foundation on top of the v0.1.0 fork-based workflow baseline.

The v0.2.0 release baseline is documented in [shared v0.2.0 release baseline](../../project/release-v0.2.0.md).

## Summary

v0.2.0 keeps `ko-KR` as the default supported locale and adds `en-US` as a foundation / experimental preset.

It introduces locale-specific config, prompts, artifact paths, Discord webhook Secret names, and provider preset naming.

## What Changed

- Added `configs/locales/ko-KR/` and `configs/locales/en-US/`.
- Added locale matrix resolution through `scripts/locale_config.py`.
- Added canonical daily artifact paths under `reports/briefs/{locale}/`, `reports/candidates/{locale}/`, and `reports/ops/{locale}/`.
- Added locale-specific Discord webhook Secret names.
- Preserved `ko-KR` legacy webhook fallback names.
- Preserved `ko-KR` legacy mirror artifacts during the v0.2 compatibility window.
- Added `en-US` prompts, source config, audience profile, and validation fixtures.
- Documented provider presets for Naver, RSS, GitHub, and Brave Search.

## Upgrade Notes

Existing `ko-KR` fork users can keep using legacy daily webhook fallback Secret names during v0.2.x.

New forks should use the locale-specific Secret names and canonical locale artifact paths.

To test `en-US`, set `CAREER_FEED_ENABLED_LOCALES=ko-KR,en-US` and add the matching `en-US` webhook Secrets before enabling Discord delivery.

## Known Limitations

- `en-US` is still a foundation/experimental preset.
- Backend Career Site Radar remains `ko-KR` centered.
- Provider marker modules exist, but provider implementation is not yet fully separated from the collector.
- No adoption, production usage, star, download, or active-user metric is claimed.
