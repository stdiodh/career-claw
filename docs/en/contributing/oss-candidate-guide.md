# OSS Candidate Suggestion Guide

> Language: [한국어](../../kr/contributing/oss-candidate-guide.md) | [English](./oss-candidate-guide.md)

OSS candidate suggestions help Career Feed recommend safe first-contribution practice for Java/Kotlin backend learners.

## Purpose

Suggest repositories, labels, or issue patterns that can improve `configs/oss-repositories.json` and the Daily Backend Brief OSS section.

## What makes an OSS candidate useful

A useful candidate is recent, open, unassigned, beginner-friendly, backend-relevant, and small enough for documentation, tests, samples, or error-message improvements.

## Beginner-friendly signals

Look for labels such as good first issue, documentation, test, help wanted, sample, or project-specific beginner labels. Verify there is no linked pull request or active owner.

## Backend relevance

Prefer Spring, JVM, Kotlin, security, testing, build tooling, HTTP, data access, or runtime topics that connect to junior backend practice.

## Safety boundaries

Do not request automation that comments on upstream issues, assigns work, opens pull requests, or changes labels. Career Feed only reviews and recommends.

## Good examples

- A recent Spring documentation issue with no assignee and clear reproduction context.
- A Testcontainers Java sample improvement issue with beginner labels.
- A Kotlin documentation issue that fits docs or sample contribution types.

## Weak examples

- Old issues with no recent creation date.
- Architecture rewrites or performance investigations without a small first step.
- Issues already claimed by another contributor.

## What Career Feed will not do

Career Feed will not bypass maintainers, claim issues automatically, or promise that a recommended issue will remain available.

## Maintainer checklist

- Repository exists in or belongs near the configured profiles.
- Recency and safe-candidate gates are satisfied.
- Contribution type is allowed.
- Fallback wording stays issue-free when no safe candidate exists.
