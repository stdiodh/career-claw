# Good Suggestion Criteria

> Language: [한국어](../../kr/contributing/good-suggestion-criteria.md) | [English](./good-suggestion-criteria.md)

A good suggestion is easy to verify, useful for the current Career Feed scope, and safe to automate.

## Summary

Suggestions should improve one of the active paths: Daily Backend Brief, Korea Dev/AI News Daily, Backend Career Site Radar, or PS progress marking.

## What a good suggestion includes

- A public URL or exact file path.
- Why it helps Java/Kotlin backend learners or junior developers.
- Freshness or update cadence.
- Region and language context.
- Known risks or limits.

## What makes a suggestion hard to review

Suggestions are hard to review when they are broad, unsourced, private, stale, unrelated to backend learning, or require unsafe scraping.

## Good examples

- A public official career page with recurring junior backend openings.
- A Spring/JVM documentation topic with a clear practice task.
- A recent OSS issue that has beginner labels and no linked work.

## Weak examples

- A private chat message.
- A paid page that cannot be reviewed.
- A news link without relevance to developer careers or backend practice.

## Region and language metadata

State whether the source is Korean, English, or another language. For new language expansion, explain how the output should stay separated from existing trees.

## Evidence and source quality

Prefer official pages, public repositories, well-maintained documentation, and sources with clear timestamps. Avoid unverifiable summaries.

## Maintainer checklist

- Source is public and stable.
- Scope matches an active workflow.
- No secret or personal data is included.
- Validation or documentation impact is clear.
